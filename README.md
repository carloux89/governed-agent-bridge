# Governed Agent Bridge

**Your agent. Your PC. Your rules.**

Developed by **Carl Cloutier**.

An installable bridge that lets an AI agent work on your own PC under your
governance: every sensitive action is proposed, justified, and approved by
you first — and everything the agent does is recorded in a tamper-evident
audit log.

Built for the Meta Global AI Developer Hackathon (Indie track, "Build for
Your World"). Demo data is 100% synthetic (fictional persona "Mme A.
Tremblay", dossier SYN-2026-001).

## Architecture

```
Task (desktop terminal)
  -> Planner (Muse Spark via Meta Model API -> JSON plan)
  -> Governance classification (read = auto / sensitive = approval queue)
  -> Executor (runs only what is allowed or approved)
  -> Hash-chained audit log -> Viewer ("Verify the chain" in one click)
```

Built with **Muse Spark** via the Meta Model API.

## Packages

- `auditlog/` — append-only JSONL log; each entry carries the SHA-256 of
  the previous entry. `verify_chain` recomputes the chain and pinpoints
  the exact entry where a tampered copy breaks.
- `approvals/` — approval queue: READ auto-approved; WRITE / EXECUTE /
  SEND / DELETE / PRINT require explicit human approval; default-deny on
  expiry. In-memory state with a JSONL journal for rebuild.
- `planner/` — planner interface (`task + context -> JSON plan` of
  proposed, risk-classed, justified steps) with a deterministic mock
  implementing the SYN-2026-001 demo scenario, and the live Spark
  planner (`planner.py` + `transport.py`, see below).
- `classifier/` — the governance ruling as data + code: effects that stay
  inside the sandbox are internal (auto-approved, audit-logged); any
  effect outside it is sensitive (explicit approval). Unknown actions
  fail closed.
- `executor/` — runs a plan step by step under the classifier and the
  approval queue: sensitive steps pause until decided (default-deny on
  expiry); every event lands in the audit chain; a sandbox guard refuses
  any path escaping the workspace.
- `dashboard/` — the demo surface: local web page on **127.0.0.1:8765**
  with pending-approval cards (Approve / Refuse), decision history, and
  the audit log with a one-click "Verify chain". Start the seeded demo
  with `python3 -m dashboard.server`.
- `demo_run.py` — the full SYN-2026-001 scenario end-to-end with the two
  approval pauses simulated; artifacts in `runs/SYN-2026-001/`.
  Note: the export PDF (`runs/SYN-2026-001/sandbox/paquet-SYN-2026-001.pdf`)
  is generated by `demo_run.py` — as a binary artifact it is not part of
  the GitHub tree; run the demo to produce it locally.

## Planner selection — mock by default, live Spark via the PC bridge

The planner is selected with the `PLANNER` environment variable
(`planner_from_env`); both `demo_run.py` and the dashboard use it:

- `PLANNER=mock` (default) — the deterministic offline planner. No
  network, identical plan every time.
- `PLANNER=spark` — the live planner asks **Muse Spark**
  (`muse-spark-1.3`, Meta Model API) for the plan. The API credential
  lives only on the user's PC (Muse config,
  `%USERPROFILE%\.config\muse\auth.json`); the call is made *on the PC*
  through the Tailscale bridge (`planner/transport.py`): a small
  PowerShell snippet reads the key locally, POSTs to the API and
  returns only the model's text. The key never leaves the PC and is
  never printed or logged.

The model's reply is parsed defensively and every step is validated
against the known action vocabulary (an action must be both executable
and classified). On **any** failure — transport, HTTP, malformed JSON,
schema violation, unknown action — the planner falls back to the mock
and records the fallback, with its reason, in the audit log
(`planner_fallback` event; `plan_produced` on success), so a run
always shows honestly which planner produced its plan, and why.

**Credits gate:** enable `PLANNER=spark` only once the hackathon Meta
Model API credits are confirmed applied to the account (expected
2026-10-28). Before they land, a live generation call would bill the
account's card instead of the credits.

## Run the tests

Python 3, standard library only:

```sh
python3 -m unittest discover -s . -t . -p "test_*.py" -v
```

## Rules of the build

- Synthetic data only — never real user data, even redacted by hand.
- No sensitive action executes without a traced human "yes".
- The audit log is append-only; verification must name the broken entry.
